Using the portal

Swagger UI is served by each microservice on its own published port (8081–8089), so the links above work both in Docker (docker compose up -d) and when services run locally. No Docker-internal hostnames are used in the browser.

Try It Out — every Swagger page has an Authorize button (top-right, lock icon). Paste the JWT access token returned by POST /api/auth/login and Swagger sends it as Authorization: Bearer <token>. Protected APIs then work directly from the UI. All services prefer the API Gateway (http://localhost:8080) as the request server inside Swagger, which keeps JWT validation centralized.

API Gateway (8080) and Eureka (8761) are infrastructure components without their own REST API surface, so they are intentionally not listed here. All business traffic goes through the Gateway at http://localhost:8080/api/....
